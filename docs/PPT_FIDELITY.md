# PPT 页面保真

LibreOffice 和 Spire 会重新解释 PPT，无法承诺与 PowerPoint 显示完全一致。
除字体之外，主题字体、字距、段落行距、文本自适应、母版、组合对象、
公式、SmartArt、图表、透明渐变、阴影、裁切和外部链接都可能产生差异。
安装原字体可减少差异，不能消除不同渲染器的全部兼容性问题。

## 使用已确认的 PowerPoint 页面

1. 在原稿使用的 PowerPoint 环境打开 PPTX，确保字体和链接资源齐全，确认各页外观。
2. 将全部幻灯片导出为 PNG，建议宽度至少 1920 像素，保持原稿宽高比。
3. 将图片压缩为 ZIP。文件名使用 `1.png`、`2.png`，或者 PowerPoint 的
   `Slide1.png`、`幻灯片1.png` 等末尾带页码的名称。允许单层或多层文件夹，
   图片必须与原 PPT 逐页对应，包含隐藏页；不要把 ZIP 本身重命名为 PNG。
4. Web 上传 PPTX 后，在该文件行点击“上传原生页面 ZIP”。校验通过后生成课程。
   服务端优先使用这组 PNG，即使批量策略仍选择 LibreOffice/Spire。

程序检查 PNG 格式、页数、连续编号、重复页码、宽高比和资源大小限制，
但无法从图片自动证明其内容属于这份 PPT，用户仍需确认页面内容和顺序。
程序将 PNG 原始字节直接复制为 `slide.png`，不重建文字、图表和布局。
文件名的编号顺序决定页面对应关系，不采用 ZIP 条目顺序。

CLI：将 ZIP 放在 PPTX 旁，例如 `课程.pptx` 对应 `课程.slides.zip`：

```sh
vidppt 课程.pptx --render-engine original
```

original 模式缺少或损坏参考页面时明确失败，不自动切回第三方排版引擎。
更换 PPTX 内容时必须重新导出配套 ZIP；CLI 不会判断旧 ZIP 是否属于新内容。
Web 将原稿和 ZIP 以新 UUID 配对存储，避免不同上传互相覆盖。

## 视频画幅与清晰度

Web“视频合成参数 → 分辨率”选择 1920×1080 或 1280×720，即为 16:9。
4:3 原稿会等比居中、两侧留边。要铺满宽屏，应先在 PowerPoint 中调整幻灯片大小，
人工检查重新布局后的页面，再导出 PNG。拉伸会变形，裁切会丢内容。

字幕、焦点高亮、数字人和包装会改变可见画面；逐像素对比原页面时应关闭这些叠加。
PNG 页面保留原始字节，最终 MP4 仍会受到缩放、视频压缩和色度采样影响，不能承诺像素完全相同。
854×480 的快速预览尤其不适合评价小字号文字清晰度。

一页一张图只能保留静态页面，无法保留原 PPT 的逐步动画、转场、音视频播放时序。
若要求这些也一致，应在 PowerPoint 原生导出视频后使用视频处理链路，当前 PNG 路径不支持。

## 缓存与部署

PPT 截图缓存现在绑定原文件内容、渲染引擎、相关库/程序版本和 Linux 字体环境；
原生页面模式还绑定 ZIP 内容。没有签名的旧缓存会重建，渲染失败不提交签名。
Docker 字体配置不再按中文语言强制前插 Noto 字体；需要重建镜像才能应用该修改。
没有原生页面 ZIP 的历史任务仍使用兼容渲染，不会自动修复为 PowerPoint 原生外观。
